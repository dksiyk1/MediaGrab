# MediaGrab · 万能解析器

Windows 桌面端的视频 / 图片解析下载工具。粘贴分享链接（或整段分享文案），
自动识别平台、解析出无水印直链，再交给内置下载器或第三方下载器（NDM）。

## 运行

### 方式一：exe（推荐）

```
dist\MediaGrab\MediaGrab.exe
```

双击即可，**不需要装 Python**。整个 `dist\MediaGrab` 文件夹可以拷到任意位置
（U 盘、另一台 Win10/11 机器都能跑），删除文件夹就是卸载。

体积 256MB，其中 playwright 的 node.exe 占 87MB（抖音图文必须靠它跑页面 JS
算签名）。这是硬成本，不是没优化。

启动时会在 `%APPDATA%\MediaGrab` 建配置目录，和源码运行共用同一份配置。

**自检**（排障用，尤其是换机器后确认功能是否完整）：

```bash
MediaGrab.exe --selftest
```

它会依次检查依赖是否打进包、playwright driver 路径是否正确、ffmpeg 能否找到，
然后真实解析 4 条链接（B站 / 小红书 / 抖音视频 / 抖音图文）。
因为 exe 是窗口程序、没有控制台，结果写在 `%APPDATA%\MediaGrab\selftest.log`。
也可以传自己的链接：`MediaGrab.exe --selftest "https://v.douyin.com/xxxx/"`。

### 方式二：从源码运行

双击 `启动 MediaGrab.bat`，或命令行：

```bash
python main.py
```

首次运行会自动创建配置目录 `%APPDATA%\MediaGrab`。

依赖（已装在内置虚拟环境中）：

```bash
pip install -r requirements.txt
```

### 启动失败排查

如果双击 bat 出现 `'xx' 不是内部或外部命令` 之类的乱码报错，是**编码问题**：

- `.bat` 文件必须是 **ANSI/ASCII 编码 + CRLF 换行**。用 UTF-8 存中文，
  cmd 会按 GBK 解析，中文字节被打乱并吞掉换行，导致后面的 `echo` 行被
  当成命令执行
- 当前这个 bat 已经改成**纯 ASCII 内容 + 全 CRLF**，不要再往里面加中文

改用命令行启动（最可靠）：

```bash
cd /d 项目所在目录
python main.py
```

用 `python.exe` 而不是 `pythonw.exe` 能看到完整报错，排查时优先用它。

如果提示缺少依赖，按上面那行 `pip install` 装，加 `-i https://mirrors.aliyun.com/pypi/simple/`
可以绕开 PyPI 文件 CDN 不通的问题。

## 支持的平台

| 平台 | 实现方式 | 视频 | 图集 | 说明 |
|---|---|---|---|---|
| B站 | 专用适配器 | ✅ | — | 双通道：**1080P 走 DASH + ffmpeg 合并**，**720P 及以下给 MP4 单文件**（NDM 可直下） |
| 小红书 | 专用适配器 | ✅ | ✅ | 解析笔记页 `__INITIAL_STATE__`，图片按 fileId 拿原图；支持 `xhslink.cn` 移动端短链 |
| 抖音 | 专用适配器 | ✅ | ✅ | 视频 H5 通道只到 720P，作品更高时自动开浏览器补 **1080P**；图文走 note 页浏览器（免登录） |
| 微博 | 专用适配器 + yt-dlp | ✅ | ✅ | 图文走页面数据接口（原图），视频交给 yt-dlp；只开一次浏览器换会话，之后 1 秒内出结果 |
| 快手 / YouTube / X / TikTok | yt-dlp | ✅ | — | 以及 yt-dlp 支持的其它 1000+ 站点 |

**降级链**：专用适配器失败会自动回退到 yt-dlp，不会一条路走到黑。

### 清晰度上限

不是固定 1080，取决于平台、作品本身和账号状态：

| 平台 | 未登录 | 登录 | 会员 |
|---|---|---|---|
| B站 | 1080P（DASH 合并） | 1080P / 1080P60 | 1080P+ / 4K / 8K / HDR / 杜比 |
| 抖音 | 1080P（作品本身有的话） | 同上 | — |
| 小红书 | 原图 / 原视频 | 同上 | — |

两条通用规律：

- **作品本身决定天花板**。抖音作品如果上传时就是 720P，接口再怎么要也只有 720P
- **高档位基本是音视频分离流**，需要 ffmpeg 合并。所以界面上会看到「需 ffmpeg 合并」
  的标注 —— 选它下载器会自动切到 yt-dlp，选单文件档才能丢给 NDM

### 优先速度 / 优先清晰度

设置 → 通用 →「优先速度」，控制要不要为更高码率多花时间：

| | 抖音视频 | B站 | 说明 |
|---|---|---|---|
| 不勾（默认） | 1080P · ~10-15s | 1080P · ~3s | 抖音多开一次浏览器，B站 多一次 yt-dlp 解析 |
| 勾上 | 720P · ~2.7s | 720P · ~1.9s | 退回单通道快路径 |

改完设置后解析引擎会重建，立即生效，不用重启。

取舍依据：抖音视频的 1080P 必须绕一趟浏览器（H5 通道只给 720P），这是唯一代价；
B站 那次 yt-dlp 只多花 1 秒，勾不勾影响不大。

## 资源嗅探（侧栏「工具 → 资源嗅探」）

解析要认识平台，嗅探不用。它开一个受控浏览器窗口，**旁听**这个浏览器的所有
网络响应，谁在播就把谁挑出来：

```
点「打开并嗅探」→ 弹出浏览器 → 在里面对着视频点播放 → 资源自动出现在列表里
```

因此它覆盖所有**网页版能看**的站点 —— 专用适配器解不了的、以及压根没写适配器的
小众站点，都能靠它兜住。

- 不需要装证书、不需要改系统代理（这点和抓包类工具不同）
- Cookie / Referer 从浏览器现场抄下来，下载直接带着走，不会 403
- 按类型筛选（视频 / 图片 / 音频 / 流），可全选批量入队
- **列表左侧直接给缩略图**：图片异步下载后按目标尺寸解码（不是先解原图再缩），
  视频用 ffmpeg 抽第 1 秒那一帧。都是后台进行，不挡列表滚动
- m3u8 分片会被合并成一条「直播流」，不会刷出几百条 `.ts`
- **同源副本只默认勾最大的**：同一个文件挂在多个 CDN 节点、或同一张图换了
  签名主机时，几条都会列出来（不藏），但只勾画质最高那条并标「最高画质」，
  避免一口气下三份一模一样的。想挑小的，自己点一下就行

判定规则在 `core/sniffer.py`：按 MIME + 后缀 + 大小三重判断，并挡掉埋点域名、
头像图标、`data:`/`blob:` 之类的伪地址。同源判定看 URL 路径（不含 query）——
同一文件换 CDN 时路径不变；路径太短（`/v.mp4`）时补上主机，免得跨站误合；
直播流不参与，因为不同直播常常都是同一 CDN 下的 `index.m3u8`。

**解析失败时会直接给出这条路**：失败卡片上的「用浏览器抓一次」会把同一个地址
带进嗅探页。多数失败不是内容没了，而是接口改版、签名过不去、风控拦了 ——
页面本身在浏览器里照常播，嗅探绕开整条解析链路就能拿到真实地址。
链接本身错（invalid）、缺组件（env）、用户取消（cancelled）这三类不给这个按钮，
打开也没有意义。

> 边界：抓不到纯 App 内的内容（比如微信 App 里的视频号），只能抓网页版。

## 账号主页批量入库

把博主 / UP 主 / 小红书账号的主页链接直接粘进输入框，会先读到作品清单，
让你勾选，勾完再批量解析：

| 平台 | 通道 | 说明 |
|---|---|---|
| B站 | 浏览器滚动（配了登录态则走 yt-dlp 分页） | `space.bilibili.com/{mid}` |
| 抖音 | 浏览器滚动 | `douyin.com/user/{sec_uid}`，无限流 |
| 小红书 | 浏览器滚动 | `xiaohongshu.com/user/profile/{id}`，多半需要登录态 |

- 读目录时不解析直链，只拿「地址 + 标题 + 时长」，几十条只要十几秒
- 一次最多 60 条，滚动 30 屏或连续 6 轮无新增就停
- 读目录的过程可取消（解析按钮会变成「取消」）
- 勾完之后仍然走原有的批量解析，所以卡片、补高清、失败重试全部复用

## 实况照片（Live Photo）

抖音 / 小红书的实况图是「一张静图 + 一段几秒的视频」。解析时会同时识别，
下载后得到一对文件：

```
作品名_01.jpg        静图
作品名_01_live.mp4   动图部分
```

同名前缀 + `_live` 后缀，放进相册能和图片配成一组。
字段提取在 `DouyinAdapter._live_url_of` 与 `xhs_adapter._live_url_of`，
拿不到就当普通静图，不会影响其他图片下载。

## 直播录制

嗅探页抓到 m3u8 后，勾上它点「录制直播流」即可边播边录，再点一次停止。

- 录制走 ffmpeg（`-c copy`，不重新编码，几乎不吃 CPU）
- 先写 `.ts` 再无损转封装成 `.mp4`：直接写 mp4 时中途中断会得到「0 秒」的坏文件，
  MPEG-TS 每个分片自带时间戳，断了也能播
- 停止时请 ffmpeg 自己收尾（写 `q`），超时才 terminate
- 转封装失败会保留 `.ts` 并提示，不会留一个打不开的 mp4
- 需要 ffmpeg：放到 `MediaGrab.exe` 同目录即可，或装进 PATH

## 批量解析与并发下载

### 一次粘贴多条

输入框里可以一次贴多行，`extract_urls` 会切出所有链接，逐条解析。

- 成功的每一条立刻变成一张卡片，不用等全部跑完
- 失败的不影响其它条，最后单独汇总成一块：列出 URL、每条试过哪些适配器、失败原因，
  带一个「重试这 N 条」按钮 —— 重试只跑失败项，已解析出来的卡片保留
- 底部进度条按「第几条 / 共几条」推进

解析是**串行**的。适配器实例持有状态（抖音的 `_last_filter_reason`、B站的 cookie 缓存），
并发跑会互相污染；抖音图文还要开浏览器，多开只会更慢。

### 并发下载

`Config.concurrency` 默认 3，设置里可调 1-4。实际并发度由
`DownloadManager._worker_count()` 按任务类型再压一次：

| 情况 | 并发度 | 原因 |
|---|---|---|
| 图集 / 直链，`auto` 或 `internal` | 配置值（上限 4） | 内置下载器每个任务独立连接，没有共享状态 |
| `ndm` 模式 | 1 | NDM 是外部进程，多开互相顶掉 |
| `ytdlp` 模式 | 1 | 它自己会起 ffmpeg，并发抢 CPU 和临时文件 |
| 批量里含 `needs_merge` 的任务 | 1 | 合并是最重的一步，逐个来反而稳 |

实测小红书 2 张图：串行 3.05s → 并发 2.81s；另一个样本 5.45s → 2.90s。

**进度条的算法**（这里踩过坑）：并发时多个文件同时上报自己的进度，如果直接把
「当前文件进度」当整体进度，会被别的文件覆盖，进度条来回跳（实测出现过 13→12、35→26）。

现在是：

```
百分比 = (已完成文件数 + Σ 各活跃文件进度) / 总数
```

并且用 `last_pct` 兜底只增不减。`tests/test_concurrency.py` 会断言进度序列单调。

## 下载队列

侧栏「下载 → 下载队列」。一次可以排多个作品，逐个自动下。

### 批次串行、文件并发

并发度已经在文件级做了（见上面「并发下载」），批次再并发会让 NDM 进程和
ffmpeg 互相抢，而且全局进度条没法表达"几个批次各自的进度"。
所以：**一个批次内 4 路并发 + 批次逐个来**。

| 场景 | 行为 |
|---|---|
| 连点几个「下载」 | 第一个立刻跑，其余显示「排队中」，前一个结束自动开始 |
| 某个批次失败 | 标记成「N 个失败」，**队列继续下一个**，不阻断 |
| 取消排队中的 | 直接移出，对应历史记录标成「已取消」 |
| 取消进行中的 | 中断当前批次，队列继续下一个 |

### 队列模式下不弹模态框

这是硬约束。排 10 个作品时只要有一个失败就 `QMessageBox`，无人值守会卡在弹框上，
后面的任务永远轮不到。所以失败只写进队列项和状态栏，重试按钮在队列卡片上。

（真正会弹框的只剩「下载中关闭程序」这一处，那是用户主动操作。）

## 关闭时的保护

还有任务没下完时关窗口会先问：

> 1 个正在下载、2 个在排队，确定关闭？
> 关闭会中断当前下载。已完成的部分会保留；未完成的会记在下载历史里，随时可以重试。

选「关闭并中断」会把排队项标成已取消、把批次里还停在 pending 的记录标成失败，
**不在历史里留一堆永远「进行中」的孤儿记录**。

下载器本身用 `.part` + `os.replace`，中断不会留下伪装成完整的残缺文件，且支持断点续传。

## B站 分P / 合集选集

多P 视频的卡片上会出现一个「共 N P」的小胶囊：

- 点开列出所有分P（标题 + 时长），选某一集会**替换成那一集的卡片**
- 菜单底部「全部 N P 加入下载队列」会逐个解析并排进队列

实现走的是最省事也最稳的一条路：**用 `?p=N` 重新解析**。
适配器的 `_parse_ids` 本来就认这个参数，不需要给适配器加新接口，
也不需要把每集的 cid 状态透传到 UI。

适配器只多做一件事：把完整分P列表塞进 `mi.extra["page_list"]`
（之前只存了 `pages` 总数，UI 读不到就只能让用户手工改 URL，12P 要粘 12 次）。

整季下载时**沿用卡片上选中的清晰度**，某个 P 没有该档位就退到该 P 的最高档，
保证一季的清晰度一致。

## 下载历史与失败重试

侧栏「历史 → 下载历史」是跨会话的账本，存在 `%APPDATA%\MediaGrab\history.db`（SQLite）。

### 两个粒度

| | 粒度 | 为什么 |
|---|---|---|
| 存储 | **一行 = 一个文件** | 「重试失败项」必须精确到单个文件。图集 20 张挂 1 张，只重试那 1 张；按作品存一行就只能整批重来 |
| 展示 | **一张卡 = 一个批次** | 用户心智是「我下过这个作品」，不是「我下过 20 个文件」。同一次点下载产生的文件共享 `batch_id` |

### 重试是原地重置，不是新建批次

失败项被重置成 `pending`、`attempts + 1`，再跑一遍。历史里一个作品始终只有**一条**时间线，
最终状态是对的；否则会留下「失败 / 失败 / 成功」三条记录让用户自己拼。
卡片上会显示「重试 2 次」。

### 记录里为什么要存那么多字段

重试要能把 `DownloadTask` 原样重建，所以每行都存了
`url / output_dir / filename / ext / referer / headers / format_selector / merge / page_url`。

少一个都不行：抖音图片少了 `headers` 里的 Cookie 就是 403（CDN 防盗链），
B站 高清少了 `format_selector` 就拼不出 `30080+30280` 的合并指令。
`HistoryRecord.to_task_kwargs()` 就是这件事的唯一出口。

### 写入时机

点下载时**先落 pending 记录再开始下**，逐个文件回写结果。这样即使程序中途被杀，
历史里也能看到「下到一半」的痕迹，而不是整条记录凭空消失。

跑完还有一层兜底：批次里仍是 `pending` 的行一律标成失败
（`DownloadWorker` 整体异常时 `on_file_done` 一次都不会触发）。

### 容量与健壮性

- 只保留最近 **200 个批次**，更早的自动清掉
- 库文件损坏（断电 / 磁盘满）时，自动改名为 `history.db.broken-<时间戳>` 后重建 ——
  历史丢了可以接受，但因为历史打不开软件就完全没法用了
- 「清空历史」只删记录，不动磁盘上的文件

## 文件名模板

设置 → 通用 → 文件名模板。留空就是标题，写模板则按变量替换：

| 变量 | 含义 |
|---|---|
| `{title}` | 标题 |
| `{author}` | 作者 |
| `{platform}` | 平台名（哔哩哔哩 / 抖音 / 小红书） |
| `{date}` | 下载当天，如 20261116 |
| `{resolution}` | 分辨率，如 1920x1080 |
| `{index}` | 图集序号 01 |

例如 `{author}_{title}_{resolution}` → `老王_今天去了哪里_1920x1080.mp4`。

两条规则：

- **写错的变量原样保留**。`{titel}` 会真的变成文件名里的 `{titel}`，
  而不是静默变空 —— 拼错时一眼就看得见。
- **图集没写 `{index}` 会自动补** `_01`、`_02`，否则十张图全叫同一个名字。
  写了就不重复加。实况照片永远带 `_live` 后缀。

渲染结果是先拼再 `safe_filename()`，`/ \ : * ? " < > |` 都会变下划线，
超长自动截断，`CON`/`NUL` 这类保留名会加前缀。

## 限速

设置 → 网络 → 单文件限速（KB/s，0 为不限）。

**对每个文件生效，不是总和**。同时下 3 个文件、限 500KB/s，实际总带宽约 1.5MB/s。

实现上分两条路：

- 内置下载器：每读完一块算"按这个速率本该用掉多少时间"，超前的部分 sleep 掉。
  sleep 拆成 0.2 秒一段，否则限 50KB/s 时一个 256KB 的数据块要睡 5 秒，
  这期间点取消完全没反应。
- yt-dlp：传 `ratelimit`，同时把 `concurrent_fragment_downloads` 压到 1 ——
  它的限速是**每个分片线程**各限一次，4 个分片就是 4 倍速度。
- NDM 由它自己管，这里设了不生效。

## 拖拽导入

把链接从浏览器地址栏直接拖进窗口就能解析；拖 `.txt` 会读取里面的链接按批量处理。

- 多条链接（换行分隔）会走批量解析
- 拖到窗口上时状态栏提示"松开即可导入"，拖到别处松手会恢复原来的文字
- 只认文本和 `.txt`；拖图片/视频文件进来没反应（本软件是下载器，不是播放器）

## 完成通知与自动关机

设置 → 通用：

| 项 | 说明 |
|---|---|
| 下载完成后通知 | 托盘气泡，报成功/失败数量。窗口在后台时状态栏看不见，这个才是有效的反馈 |
| 全部完成后 | 什么都不做 / 关机 / 睡眠 |

几条约束，都是为了"挂机下载"不坑人：

- **整个队列跑完才触发**，不是每个文件。排队 10 个作品时不会下完第一个就关机
- **只要有一个文件失败就不执行**，免得醒来发现没下完
- **取消的任务不算成功**，不会触发
- 关机有 60 秒缓冲，反悔可以在终端执行 `shutdown /a`
- 没勾「关闭时最小化到托盘」时托盘图标是隐藏的，而隐藏状态下气泡弹不出来 ——
  所以通知时会临时亮一下图标，8 秒后收回

### 关于 NDM

1. 优先执行 `NeatDM.exe "<直链>"`，把地址投递给已有或新起的 NDM 进程

## 已踩过的坑（都已在代码里处理）

- **小红书图片 `urlDefault` 直连 403**：那是 webpic 缩略图 CDN，必须用
  `fileId` 拼 `sns-img-qc.xhscdn.com/{fileId}` 才能下载
- **小红书原图是 HEIC**：Windows 打不开，下载后自动调 ffmpeg 转 JPG
- **小红书移动端短链会跳登录页**：`xhslink.cn/o/xxx` 无 Cookie 时 302 到
  `xiaohongshu.com/login?redirectPath=...`，真实地址藏在 redirectPath 里，要解开这层
- **Referer 不能用短链域名**：小红书 CDN 对 `xhslink.cn` 这个 Referer 直接 403，
  必须是 `www.xiaohongshu.com`。所以 `MediaInfo` 单独带了 `referer` 字段
- **B站 mcdn 节点在部分网络下 TLS 握手失败**：所以 B站 走 playurl 的
  `platform=html5` 接口，拿的是传统 CDN 直链
- **B站的 1080P 不在 html5 通道里**：`platform=html5` 只给到 720P（好处是单个
  MP4、免合并、NDM 能直下）。1080P 及以上只存在于 DASH，必须音视频分离下载再合并。
  yt-dlp 走 PC 通道，**未登录也能拿 1080P**（1080P+ / 4K 才要大会员），
  所以 B站 现在两条并存：yt-dlp 给高清合并档，html5 给单文件档
- **抖音 H5 的 feed 通道只下发到 720P**：`video.width/height` 经常是 1080×1920，
  但 `bit_rate` 里最高只有 720×1280 —— 分辨率字段和实际码率表不一致。
  完整档位只在 PC 页的 `web/aweme/v1/web/aweme/detail/` 里（带 a_bogus 签名）。
  所以解析时先看「作品原始分辨率 vs feed 最高档」，**只有确实有提升空间**才开浏览器，
  否则保持 2 秒的快路径
- **抖音详情接口已关闭**：`aweme/v1/aweme/detail/` 对所有视频都返回空（连热门视频也是），
  视频改用 `aweme/v1/feed/?aweme_id=xxx&aid=1128&count=1`，它会把目标视频排在第一位。
  **这个接口对多余参数极敏感**，多加 `version_code` / `device_platform` 就返回空
- **抖音图文不能走 `slidesinfo`，要走 note 页**：`web/api/v2/aweme/slidesinfo/`
  只认"幻灯片"（slides）类型，普通图文作品（note）请求它会被回
  `filter_list.reason = 8` —— 这个数字很容易被误读成"内容不可用/已被限制"，
  其实只是问错了接口。正确做法是打开 `www.douyin.com/note/{id}`，页面用自己的
  `a_bogus` 签名把详情拉下来并渲染成 `<img>`，直接读 DOM 就行，不用管签名。
  `/share/slides/{id}/` 只留给真正的 slides 类型
- **抖音图片 CDN 校验浏览器 Cookie**：`*-sign.douyinpic.com` 不带 Cookie 一律 403。
  所以解析时把这次浏览器会话的 Cookie 存进 `MediaItem.headers`，
  由内置下载器带下去（NDM 是独立进程传不了请求头，遇到带 Cookie 的任务会自动
  降级到内置下载器）
- **抖音图片 URL 不能改写**：签名绑在完整 URL 上，手拼 `~noop.jpeg`（原图模板）或
  去掉 `~tplv-` 后缀都会 403；只能原样使用页面给出的 URL
- **抖音笔记要等图替换完成**：首屏先铺 webp 缩略版，随后换成原尺寸。固定 sleep
  要么等不够要么白等，改成轮询到图片 URL 列表连续两次不变才取值
- **抖音图文取 `url_list` 而不是 `download_url_list`**：后者是带水印版本
  （`tplv-dy-water-v2`），前者 `tplv-dy-aweme-images` 是无水印原图。
  note 页拿到的图本身不带水印，只需按 URL 判断真实格式（webp/jpeg），
  扩展名写错文件就打不开
- **抖音分享页必须用移动端 UA**：PC UA 会被重定向到 SPA 空壳页（72KB，零数据）
- **抖音分享页风控抖动**：同一请求可能返回完整 H5（含 `__ROUTER_DATA`），也可能返回
  2.5KB 空壳页，所以代码里做了多组合重试 + 失败降级
- **PyPI 文件 CDN 不通时 pip 会卡死**：用阿里云镜像
  `-i https://mirrors.aliyun.com/pypi/simple/`

### 几个不能改错的地方

- **圆角不能用 `setMask`**。像素级裁剪没有抗锯齿，12px 圆角边上全是台阶。
  现在由各自绘制的控件负责：`Root` 画壁纸圆角路径、`Sidebar` 用 `QPainterPath`
  裁左侧两角、`#Content` / `#Toolbar` / `#StatusBar` 用 QSS 的 `border-radius`
  裁右侧两角。子控件不会被父级的 clip 裁到，所以必须逐层处理。
- **frameless 的拖拽用 `startSystemMove()`**，不要自己算 `mouseMove` 位移 ——
  后者在高 DPI 和多屏下会漂。可拖动区域只有侧栏顶部那条和工具栏中段（`DragHandle`）。
- **右下角不要用 `QSizeGrip`**。它自带三角纹理，在浅色圆角窗口上非常突兀。
  换成不绘制的 `ResizeGrip`，内部调 `startSystemResize(Bottom|Right)`。
- **分段控件超过 4 档自动降级为下拉框**。B站 有 8K/4K/1080P60/1080P+/1080P/720P
  七八档，硬塞分段会挤爆。`FormatSelector` 对外只暴露 `currentData()`，调用方不用
  关心里面是哪种形态。分段里只放短标签（`resolution`），完整描述进 tooltip。
- **字体栈里 Segoe UI 家族必须排在 SF Pro / -apple-system 前面**，否则 Windows 上
  emoji 字形会被吞成方块。（这条和设计稿里踩的是同一个坑）

### 侧栏不是装饰

分组计数、磁盘容量全部是真数据：

### 结构：内容从玻璃下面滚过去

这是整套材质成立的前提。布局改成了**列表铺满整窗，工具栏与底部栏浮在上层**：

- 滚动时按 ~15fps 刷新（`QTimer` 66ms，`valueChanged` 触发，停手 0.3s 后停），

- 浮空层和列表都装 `wheelEvent` 转发，鼠标压在玻璃条上也能滚列表

### 材质：四层叠加

QSS 表达不了模糊和折射，材质是 `mediagrab/ui/glass.py` 里手绘的：

| 层 | 做法 | 作用 |
|---|---|---|
| 背景 Aurora | 四角柔光斑 + 中央提亮 | 列表之外的地方要有壁纸感，否则页面是死白 |
| 背景采样 | 卡片采 Aurora，浮空条采滚动视口 | 该位置背后的东西真的透过来 |
| 磨砂 | 1/4 降采样 → 高斯 → 回放，整窗约 5ms | 毛玻璃散射 |
| 高光 / 折射 | 上亮下暗的渐变描边、上沿镜面横线、底部暗边 | 让它看起来是玻璃而不是白纸 |

细节：
- 列表里的卡片 `GlassPanel` 外层留 6px 画投影；浮空条 `pad=0`（投影画不到控件
  外面，留白只会露出一条没被磨砂的清晰内容）
- 鼠标悬停时材质 180ms 缓动变亮，并有跟随指针的移动高光
- 环境染色：面板背后区域缩到 1x1 取平均色，按 22% 掺进白层
- 乳白层 / 斜向高光 / 底部厚度**合并成一条渐变**填充，绘制开销减半
- 浮空条的不透明度（`tint`）比列表卡片高：它背后是内容，太透会显脏

### 图片预览

缩略图右上角的放大图标、或者双击缩略图，都能打开全屏预览。

- 底层是**打开瞬间抓的主界面截图 + 高斯磨砂**，再叠暗色遮罩 —— 所以预览不是
  一块纯黑色板子，背后仍然能感觉到内容，和整体材质语言一致
- `← →` / 滚轮切换，首页尾页循环；`ESC` 或点图片外的空白处关闭
- 图片按 `devicePixelRatioF()` 缩放到物理像素，高分屏上不发虚
- 预览直接用缩略图阶段缓存的原始字节，不再回服务器要一遍

两个容易踩的点：

- **双击不能改变选中状态**。Qt 的双击序列是 `Press → Release → DblClick → Release`，
  第一下 `Press` 已经把选中翻了，`DblClick` 里要按"按下前的状态"还原。
  但有些输入设备/自动化只发 `DblClick` 不发前置 `Press`，所以还原前要先判断
  有没有记录，不能无条件反向翻
- **按钮必须 `setFocusPolicy(Qt.NoFocus)`**。否则点完箭头按钮焦点跑到按钮上，
  预览层收不到 `ESC`

### 参考过哪些实现，为什么最后这么写

| 项目 | 做法 | 我们用不用 |
|---|---|---|
| [shayann07/liquidglass](https://github.com/shayann07/liquidglass) | 按 iOS 26 录像逐帧标定的材质：SDF 几何 + Snell 折射 + 色散 + 边缘光。Qt 端是 QML `ShaderEffect` 采样它背后的 QML item | 数学**移植了**（`glass_optics.py`），但默认关闭，原因见下 |
| [OliverZhaohaibin/Qt-liquid-glass-widgets](https://github.com/OliverZhaohaibin/Qt-liquid-glass-widgets) | PySide6 + QML，`MultiEffect` 做模糊 + GLSL 噪声畸变 + Fresnel + 指针跟随高光 | 借鉴了"指针跟随高光"和"环境染色"两个 token |
| [fsalinas26/qt-liquid-glass](https://github.com/fsalinas26/qt-liquid-glass) | 直接调 macOS 的 `NSGlassEffectView` | 不能用：只在 macOS 生效 |
| [Akascape/py-window-styles](https://github.com/Akascape/py-window-styles) | Windows 11 的 DWM Mica / Acrylic，窗口级系统合成 | 未采用，见文末 |

**折射实测结论：在 Aurora 背景上无效，但在滚动内容上有用。**
`glass_optics.py` 是 SDF + 边缘外采样 + 色散的 CPU 移植（每块 780×200 约 8ms）。
把开关打开、与关闭版本逐像素比对：

```
卡片（背后是 Aurora 渐变）  tint=174：平均色差 0.11 级，最大 3 级，差异像素 0%
卡片                     tint=40： 平均色差 0.13 级，最大 6 级，差异像素 0.04%
```

原因是数学上的：折射是**位移**，位移一个平滑渐变几乎等于恒等变换。
而浮空条背后是滚动的卡片（高频内容），模糊本身就够了，折射依旧看不出来。
所以这份实现留在代码里（`MEDIAGRAB_GLASS_OPTICS=1` 打开，需要 numpy），默认不走。

同一批实现里真正**可见**的是另外两件事，已经默认启用：环境染色（3-8 级色偏）
和指针跟随高光。这也是为什么最后动的是这两处，而不是折射。

## 解析失败诊断

失败不再只是「解析失败」四个字。引擎会记下每条链路试了什么、花了多久、为什么挂，
归成一个原因，再给出对应的动作：

| 原因 | 读作 | 界面给的按钮 |
|---|---|---|
| 链接不对 | 复制时截断了 / 贴的是主页 | 换链接重试 |
| 需要登录 | 会员内容、关注可见 | 去配登录信息 |
| 被平台拦了 | 风控 / 验证码 / 请求太频繁 | 用浏览器登录态重试 |
| 解析组件过期了 | 平台改了接口，本地规则对不上 | 更新解析组件 |
| 网络不通 | 断网 / DNS / 代理 | 检查网络设置 |
| 内容不在了 | 已删除 / 私密 | 换链接重试 |

判「改版」主要靠**异常类型**而不是文案：适配器里冒出 `KeyError` / `AttributeError`，
几乎必然是平台把字段改了。这类信号比任何自然语言判断都准，所以它优先于关键词。

### 每次解析都记一笔

`%APPDATA%\MediaGrab\logs\parse.jsonl`，一行一次，成功失败都记。
「设置 → 更新 → 复制诊断信息」会汇总成：环境版本、每个平台的成败次数与成功率、
连续失败次数、最近十二条失败的原始报错。粘这个比截图有用。

连续失败 3 次以上、且原因是「改版 / 被拦」时，失败块会多一句
「该平台最近连续 N 次没有成功」—— 这就是「这个平台是偶尔抽风，还是真的变了」的判据。

## 更新

分两条路，因为风险和收益完全不同。

### 解析组件（yt-dlp）：全自动

yt-dlp 每周跟着平台改版，不更新它会慢慢变哑。它是纯 Python 包，下载下来解压到
`%APPDATA%\MediaGrab\runtime\` 就能用，不动程序本体。

「设置 → 更新 → 更新到最新」。更新完立刻生效（会丢掉已导入的旧模块），下次启动也从新版加载。
装坏了自动回退内置版本。

实现上不能只改 `sys.path`：PyInstaller 的 finder 挂在 `sys.meta_path` 上、查的是打包时的
TOC，PYZ 里的旧版会先命中。所以用一个前置 finder 抢在它前面，并且连子模块一起接管 ——
否则会出现「顶层包用新版、extractor 用旧版」的混装。

### 程序本体：检查 + 一键替换

在设置里填一个更新源（`update.json` 的地址），启动 4 秒后静默检查，最多 24 小时一次。
有新版本时在结果区顶部插一条提示，同一个版本只提示一次。

`update.json` 的格式：

```json
{
  "version": "0.3.0",
  "exe_url": "https://example.com/mg/MediaGrab.exe",
  "exe_sha256": "…",
  "page": "https://example.com/mg/",
  "notes": "修了抖音图文"
}
```

```bash
python tools/make_update_json.py --version 0.3.0 --base https://example.com/mg/
```

sha256 从打包产物现算，不用手抄 —— 抄错的后果是每个用户下载完都校验失败。

替换只换 exe：Python 代码都编在这一个文件里，`_internal` 是 Qt / Playwright 那些运行时，
版本更新通常不动它们。旧文件保留成 `MediaGrab.exe.old`。
**前提是这次更新没有引入新的第三方依赖**，所以这一步做成「用户点确认才做」，不替用户决定。

## 已知限制

- 抖音 / 微博的反爬策略变化很快，不保证 100% 成功率
- 小红书视频笔记和图文笔记的解析成功率依赖页面结构，平台改版需要跟
- B站 番剧、直播走 yt-dlp 兜底，未做专用适配；分P 选集也只在普通投稿上验证过
- **没有托盘**：关掉程序 = 队列停摆。所以关闭时会拦一道确认，不会静默丢任务
- **队列不持久化**：排队项只存在内存里，关掉就没了（历史记录保留，可以重试）
- 「已完成」这个筛选是本次会话内的统计，不跨进程
- 窗口是 frameless 的，Windows 的 `Alt+Space` 系统菜单和贴边分屏用不了；
  拖动靠侧栏顶部和工具栏中段，缩放靠右下角热区

## 剩下的一个可选项：窗口级 Mica

现在已经做到"内容从玻璃下穿过"，这是 iOS 那套材质的标准用法。再往上只有一条路：

**窗口级 Mica / Acrylic**（Win11 可用，本机 build 26200 支持）
用 `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` 让窗口半透明，
背后是真实桌面壁纸，由 DWM 做 GPU 合成，零 CPU 开销。

没做的原因：它是**窗口级**材质，DWM 的合成结果拿不回读，所以面板无法再各自
采样背景 —— 一旦启用，"每块面板自己的液态玻璃"就不存在了，观感会从 iOS 变成
Windows 11 应用的样子，而且壁纸深浅会影响文字对比。这属于换风格，不是增量改进。

## 打包

```bash
build.bat
# 等价于
python -m PyInstaller build.spec --noconfirm
```

产物 `dist\MediaGrab\MediaGrab.exe` + `_internal\`，整个文件夹一起分发。

### 为什么是 onedir 而不是 onefile

| | onedir（当前） | onefile |
|---|---|---|
| 启动 | <2 秒，直接读文件 | 5-10 秒，每次都要把 256MB 解压到 `%TEMP%` |
| 体积 | 256MB | 约 120MB（压缩过） |
| 风险 | 无 | playwright 的 `node.exe` 在临时目录里容易被杀软拦，且每次退出都会删除解压内容 |

VS Code、GitHub Desktop 这类程序也都是 onedir。要给别人发一个文件就打个 zip。

### build.spec 里几个不能删的配置

| 配置 | 为什么 |
|---|---|
| `collect_all("playwright")` | driver 目录（node.exe + npm 包）必须按原相对路径进包。playwright 用 `inspect.getfile(playwright).parent / "driver"` 定位，路径差一层就起不来，而且只会在解析抖音图文时才报错 |
| `collect_all("yt_dlp")` | extractor 是动态导入的，不收集就只能解析极少数站点 |
| `collect_all("curl_cffi")` | 自带 libcurl dll，不收集会缺依赖 |
| `hiddenimports` 里的自家模块 | 适配器在 `engine.reload_adapters()` 里函数内 import，静态分析容易漏 |
| `excludes` 里**不能**有 `sqlite3` | browser_cookie3 读 Chrome/Edge Cookie 要用它 |
| `excludes` 里**不能**有 `shiboken6` | PySide6 的本体绑定层 |

### 打包后才知道的三件事

1. **`sys.stdout` 是 `None`**。`console=False` 的 exe 没有标准流，任何
   `print()` 都会 `AttributeError`，第三方库一打日志就崩在无关的地方。
   `main.py::_redirect_std_streams()` 把它挂到 devnull。
2. **`QBuffer(QByteArray())` 会崩**。生成图标时传临时对象，Python 侧没有引用，
   C++ 侧成了悬空指针，进程直接 `exit 127` 且没有任何报错。
   改成落盘再读回。
3. **ffmpeg 没有内置**。本机这个是 shared build，`ffmpeg.exe` 只有 538KB 但依赖
   240MB 的 `avcodec/avfilter` dll，塞进包里体积翻倍不值。
   `find_ffmpeg()` 现在优先查 **exe 同目录 → exe/bin 子目录 → PATH → 常见路径**，
   换机器时把 `ffmpeg.exe` 丢到 exe 旁边就行，不用配环境变量。
   没有 ffmpeg 只影响两件事：小红书 HEIC 原图转 JPG、B站 DASH 流的音视频合并。

## 测试

```bash
python tools/run_tests.py --fast     # 20 个用例文件，跳过联网用例，约 2 分钟
python tools/run_tests.py            # 含真实链接/真实下载，慢很多
python tools/lint.py                 # 静态检查（未使用变量、未定义名、重复 key）
```

`tests/` 里带 `test_` 前缀的并非都是自动化用例 —— `test_parse.py` 是 `test_parse.py <url>`
这种手动工具，`test_e2e.py` 要真实网络，`run_tests.py` 的 `MANUAL` 里列了排除清单。

两个坑：

1. **不要让测试进程的 stdout 挂管道**。`subprocess.run(capture_output=True)` 时，
   PySide6 偶发在退出路径上 abort（同一用例直接跑是干净的），退出码变成
   `0xC0000409`，看起来像测试挂了其实断言全过。`run_tests.py` 因此直写日志文件。
2. **GUI 用例别用 `sys.exit()` 收尾**。PySide6 6.12 在解释器 finalization 阶段
   销毁 `QApplication` 有概率 abort，断言早已跑完。用例里用 `os._exit(code)`
   直接交付退出码（`test_progressive_upgrade.py` 就是这么写的）。

## 加一个新平台


1. 在 `mediagrab/core/adapters/` 新建 `xxx_adapter.py`，继承 `BaseAdapter`
2. 实现 `parse(url) -> MediaInfo`，填好 `formats`（视频）或 `items`（图集）
3. 在 `engine.py` 的 `reload_adapters()` 里注册

4. 在 `registry.py` 的 `_DOMAIN_RULES` 加域名匹配

主流程、下载层、UI 都不用动。
